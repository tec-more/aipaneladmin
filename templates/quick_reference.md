## 🎯 一分钟快速开始

### 最简单的使用方式

```markdown

实现 [功能名称]

## 参考
API文档: [链接]

## 要求
1. 分析文档提取参数
2. 设计Schema和Service
3. 实现API路由
4. 遵循项目代码风格
```

## 📋 标准三段式模板

### 1. 需求描述（必填）

```markdown
### 功能需求
[一句话描述]

### 参考文档
[API文档链接或内容]

### 实现要求
- 接口1: POST /xxx/yyy - 功能说明
- 接口2: GET /xxx/zzz - 功能说明
```

### 2. 上下文信息（推荐）

```markdown
### 技术栈
FastAPI + Tortoise-ORM + MySQL

### 项目结构
base/plugins/xxx/
├── api/v1/
├── models/
├── schemas/
└── services/

### 参考代码
base/plugins/yyy/api/v1/zzz.py
```

### 3. 执行指令（必填）

```markdown
### 请执行
1. 提取API关键信息（参数、响应、错误码）
2. 设计Schema和Service
3. 生成完整代码
4. 提供使用示例
```

## 🔧 调试技巧

### 如果AI生成的内容不符合预期

#### 问题1: 信息提取不完整
**解决**: 明确指出遗漏的内容
```
"你遗漏了XX参数，请重新分析文档第Y章节"
```

#### 问题2: 代码风格不一致
**解决**: 提供参考代码并明确要求
```
"请严格参考 base/plugins/xxx.py 的代码风格"
```

#### 问题3: 缺少错误处理
**解决**: 明确错误处理要求
```
"请添加所有错误码的处理逻辑"
```

#### 问题4: 代码过于复杂
**解决**: 要求简化
```
"请简化实现，只需要核心功能即可"
```

## 🎓 进阶提示

### 提示1: 分阶段交互
不要一次性给太多信息，分步骤：
1. "请分析这个API文档，提取关键信息"
2. "基于上面的分析，设计Schema"
3. "现在生成完整的代码实现"

### 提示2: 提供上下文
给AI看项目中的类似实现：
```
"这是项目中微信支付的实现，请参考这个风格实现支付宝"
```

### 提示3: 约束条件
明确告诉限制：
```
"不要使用第三方SDK，直接用requests库调用"
"使用Tortoise-ORM的异步语法"
"所有配置从config.ini读取"
```

### 提示4: 迭代优化
```
"生成的代码可以，但需要优化：
1. XX函数太长，请拆分
2. YY注释不够详细
3. 请添加ZZ边界情况处理"
```

## 🚫 常见错误

### ❌ 错误示例

```
"帮我写一个支付功能"
→ 信息太少，AI无法准确理解
```

```
"实现这个API"
→ 只给了链接，没有说明需求
```

```
"生成代码"
→ 没有上下文和参考信息
```

### ✅ 正确示例

```
"实现微信Native支付，文档在xxx。
需要：1.创建订单返回二维码 2.轮询查询状态
参考：base/plugins/alipay的代码风格"
→ 清晰、完整、有参考
```
