### 3.2 System Prompt 编写指南

**关键要素**：

1. **角色定义**：明确智能体身份
2. **能力边界**：说明能做什么，不能做什么
3. **行为准则**：如何回应用户
4. **输出格式**：结构化输出要求
5. **安全规则**：安全约束条件
6. **反思逻辑**：自我校验机制

**示例模板**：

```
你是一个专业的[角色名称]，负责[核心任务。

你的能力：
- 能力1
- 能力2
- 能力3

你的边界：
- 不越权操作
- 不编造信息
- 保护用户隐私

行为准则：
- 友好专业
- 准确高效
- 主动帮助

输出格式：
{
  "思考": "你的思考过程",
  "行动": "执行的操作",
  "结果": "最终答案"
}

安全规则：
- 不涉及敏感内容
- 遵循公司政策
- 保护用户数据

反思逻辑：
先思考→再行动→观察结果→校验是否正确
```

## 五、最佳实践

### 5.1 智能体设计原则

- **以人为本**：人可以随时介入，智能体始终服务用户
- **明确边界**：清楚能做什么，不能做什么
- **安全第一**：权限控制、数据脱敏、内容风控
- **可解释性**：决策过程透明，可追溯
- **持续迭代**：基于反馈不断优化

### 5.2 提示词工程最佳实践

1. **角色明确**：给智能体清晰的身份定位
2. **示例引导**：提供具体的例子说明期望输出
3. **格式规范**：明确输出的结构化格式
4. **约束清晰**：说明不能做什么
5. **反思机制**：加入自我校验逻辑

### 5.3 记忆管理最佳实践

1. **短期记忆**：对话上下文、关键信息
2. **长期记忆**：用户偏好、历史经验
3. **工作记忆**：当前任务状态
4. **记忆检索**：相关度排序、时效性考虑

### 5.4 RAG 最佳实践

1. **数据质量**：清洗、去重、标准化
2. **分块策略**：合理的文档切分
3. **检索策略**：混合检索、重排序
4. **知识校验**：事实核查机制

## 八、常见问题

### Q1: 如何选择推理策略？

- **function_call**：适合工具调用为主，流程固定场景
- **react**：适合需要思考-行动-观察循环的复杂场景

### Q2: Memory 选择 public 还是 private？

- **public**：跨用户共享记忆，适合通用知识
- **private**：用户私有记忆，适合个人偏好

### Q3: 如何优化 Prompt？

1. 收集失败案例
2. 分析问题原因
3. 调整提示词
4. A/B 测试对比
5. 持续迭代优化

### Q4: 如何处理幻觉问题？

1. 增强 RAG 知识库
2. 增加事实校验节点
3. 优化提示词约束
4. 人工审核机制
5. 用户反馈收集
