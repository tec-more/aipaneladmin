## 1. 核心流程（时序说明）

### F1 编辑 → 保存 → 发布主流程

```
用户(M1画布)          M3工作流服务           M8权限          M5/Qdrant
   │ 编辑草稿             │                    │                │
   │── PUT /draft ───────►│ 服务端全量校验      │                │
   │                      │── 资源引用授权校验 ─►│                │
   │◄─ 200 + version ─────│ (乐观锁: draft_ver) │                │
   │ 点击发布              │                    │                │
   │── POST /publish ────►│ 再次全量校验        │                │
   │   Idempotency-Key    │ 生成不可变 version  │                │
   │                      │ 绑定资源快照ID清单   │                │
   │◄─ 201 {version_no} ──│                    │                │
```

规则：发布即冻结；已发布版本只读；草稿再编辑后发布产生 version_no+1；运行实例绑定 version 快照。

### F2 试跑流程（草稿态）

```
用户 ── POST /workflows/{id}/dry-run (SSE) ──► 接入层：归属校验 → 配额预估(M9)
     ◄── 429 额度不足（预估超）──
     │ 通过 → M2 引擎以 draft JSON 执行（不写版本，标记 execution.kind=dry_run）
     ◄── SSE 事件流（§5）──
     结束 → 计量结算(M9) → Trace 落库（用户可见，kind=dry_run 可筛选）
```

试跑限制：不写长期记忆；不影响已发布版本；单用户试跑并发=1。

### F3 对话执行主流程（发布态）

```
用户 ── POST /agents/{id}/chat (SSE) ──► 归属/发布态校验 → 会话上下文装载
  → 配额预估（消息+上下文长度启发式）→ M2 执行（绑定当前发布 version）
  → SSE 流式输出 → 结算 → Trace + 记忆写入(private 按主体)
```

### F4 节点失败重试流程

```
节点失败 → 判定错误类别：
  可重试(超时/限流/5xx) → 指数退避重试：1s/2s/4s，上限 3 次（节点配置可下调，不可上调）
  不可重试(校验/授权/4xx) → 直接失败
重试耗尽 → 节点失败策略(图配置)：fail_fast(默认) | continue_with_default(仅允许声明默认值的节点)
最终失败 → run_failed 事件 + 结算（已耗用部分照计）+ Trace 标记
```

### F5 取消与断点

```
取消：POST /executions/{id}/cancel → 协作式取消：当前节点完成或下一个调度点终止
  → LLM 流式中断（关闭上游连接）→ 状态 cancelled → 结算已发生部分
断点：检查点(checkpoint)按节点边界写入 → 进程重启后运行中实例标记 interrupted
  → P0 仅支持"查看"，不支持自动恢复（恢复依赖 MQ 执行器，P1）
```

### F6 HITL 暂停/恢复

```
HITL 节点到达 → run_paused 事件 + 任务单生成（assignee 按 M11 解析）
  客户域：P0 仅 self；后台域：按角色 data_scope
审批人 ── POST /executions/{id}/resume {approved, comment} ──► 校验审批人资格
  → 注入 HITL 结果变量 → 从暂停节点继续 → 全量审计留痕
超时：72h 未处理 → 按节点配置 timeout_action(fail/skip)
```

### F7 配额拦截流程

```
请求进入 → M9 预估 → Redis 原子预占(quota_hold)
  不足 → 429 + 看板提示（不进入引擎，零模型调用）
  充足 → 执行 → 每节点结算真实用量(usage_record) → 预占转正式/释放差额
```

### F8 越权访问流程

```
任何资源请求 → M8：归属匹配？否 → 404（不暴露存在性）+ 审计(warn)
资源引用（KB/模型/工具）→ M8：ResourceGrant 存在？否 → 校验错误 E-110（保存/发布时，PRD §4.5 为 E-1xx 权威来源）/ 403（运行时）
异常高频越权（同主体 1 分钟 > 10 次）→ 限流 + 审计(alert)
```

## 2. API 列表

### 2.3 接口入出参 Schema（关键样例）

**POST /v1/u/workflows/{id}/publish → 201**
```json
{"code":0,"data":{"version_id":1024,"version_no":3,"published_at":"2026-11-01T10:00:00Z"}}
```

**POST /v1/u/workflows/{id}/dry-run → SSE（见 §5）**，请求体：
```json
{"inputs":{"query":"帮我总结这份文档","file_ids":[12]}}
```

**GET /v1/u/quota → 200**
```json
{"code":0,"data":{"plan":"svip","period":"2026-11","items":[
  {"item":"llm_tokens","limit":2000000,"used":153200,"held":8000},
  {"item":"concurrent_runs","limit":5,"used":1},
  {"item":"kb_count","limit":100,"used":12}]}}
```

**统一错误**
```json
{"code":42901,"message":"额度不足，预计消耗 12000 tokens，剩余 8000","data":{"item":"llm_tokens"}}
```

错误码段：`401xx` 鉴权、`403xx` 越权/未授权、`404xx` 归属不可见、`409xx` 乐观锁/状态冲突、`422xx` 校验失败（含 E-101~E-113）、`429xx` 配额/限流、`500xx` 引擎内部。

## 3. 工作流 JSON Schema v2（VueFlow 与引擎双兼容）

设计原则：**schema 字段名直接对齐 VueFlow 运行时结构**，前端渲染零转换；引擎解析同一份 JSON。

```json
{
  "schema_version": 2,
  "meta": {"name": "客服助手", "description": "...", "icon": "bot"},
  "variables": [
    {"name": "query", "type": "string", "required": true, "source": "user_input"},
    {"name": "user_level", "type": "string", "source": "context", "sensitive": false}
  ],
  "nodes": [
    {
      "id": "n_start", "type": "start",
      "position": {"x": 80, "y": 200},
      "data": {"label": "开始", "config": {}, "outputs": [
        {"name": "query", "type": "string"}
      ]}
    },
    {
      "id": "n_rag", "type": "rag_retrieval",
      "position": {"x": 340, "y": 200},
      "data": {"label": "知识检索", "config": {
          "kb_ids": [3], "top_k": 5, "score_threshold": 0.6, "rerank": false},
        "inputs": [{"name": "query", "type": "string", "from": "n_start.query"}],
        "outputs": [{"name": "chunks", "type": "array<chunk>"}]
      }
    },
    {
      "id": "n_llm", "type": "llm",
      "position": {"x": 620, "y": 200},
      "data": {"label": "回答生成", "config": {
          "model_id": "m_gpt4o", "temperature": 0.3, "max_tokens": 2048,
          "prompt_template": "基于资料回答：{{n_rag.chunks}}\n问题：{{query}}"},
        "inputs": [
          {"name": "chunks", "type": "array<chunk>", "from": "n_rag.chunks"},
          {"name": "query", "type": "string", "from": "n_start.query"}],
        "outputs": [{"name": "answer", "type": "string"}]
      }
    },
    {"id": "n_end", "type": "end", "position": {"x": 880, "y": 200},
     "data": {"label": "结束", "config": {"output_mode": "last"},
      "inputs": [{"name": "answer", "type": "string", "from": "n_llm.answer"}],
      "outputs": []}}
  ],
  "edges": [
    {"id": "e1", "source": "n_start", "sourceHandle": "out", "target": "n_rag", "targetHandle": "in"},
    {"id": "e2", "source": "n_rag", "sourceHandle": "out", "target": "n_llm", "targetHandle": "in"},
    {"id": "e3", "source": "n_llm", "sourceHandle": "out", "target": "n_end", "targetHandle": "in"}
  ],
  "settings": {"timeout_s": 300, "retry": {"max": 3, "backoff": "1,2,4"},
               "trace_level": "standard", "memory_mode": "private"}
}
```

**VueFlow 兼容说明**：nodes/edges 的 `id/type/position/source/target/sourceHandle/targetHandle` 与 VueFlow 完全同构，画布直接消费；`data.config/inputs/outputs` 为业务载荷。条件边：`edges[].condition`（表达式）仅在 condition 节点出边上出现。**v1 兼容**：转换器将旧 LangGraph JSON（nodes/links 结构）映射为本结构，引擎只解析 v2。

## 4. 节点数据契约与变量类型

### 4.1 变量类型（12 类，对齐 PRD §4）

`string / number / boolean / date / file / chunk / message / object / array<T> / any / secret(仅平台注入) / stream(内部)`

兼容规则：同名同型直连；`any` 双向兼容；`array<T>` 与 `T` 间须经循环/迭代节点显式转换；`secret` 不可出现在变量绑定与 prompt 模板插值之外的位置；类型不匹配 → E-101（编辑期阻断，PRD §4.5 为 E-1xx 权威来源）。

### 4.2 节点执行契约（引擎统一信封）

```
NodeInput  = { config, resolved_inputs, context: {owner, quota, trace_id, session} }
NodeOutput = { status: success|failed|paused, outputs: {...}, usage?: {tokens_in, tokens_out},
               error?: {code, message, retryable}, next?: [node_ids] }
```

10 类节点的 config/inputs/outputs 明细**直接采用 PRD §5 定义**，此处不再重复；引擎侧以本信封包裹，SSE 事件由信封转换生成。

### 4.3 用户侧节点能力开关（C-04）

| 节点 | 用户域 | 说明 |
|---|---|---|
| start/end/llm/rag/condition/loop/sub_workflow/hitl/sub_agent/template | 开 | — |
| http | 受控 | 域名白名单（管理员维护），禁内网段（10/172.16/192.168/127/169.254） |
| code | 关 | 用户域永久禁用，schema 校验直接拒绝 |

## 5. 流式输出与 Trace 链路透传

### 5.1 SSE 事件结构（对齐 PRD 6.5 八类）

```
event: run_started      data: {"execution_id":9102,"version_id":1024,"ts":...}
event: node_started     data: {"node_id":"n_llm","label":"回答生成","seq":3}
event: token            data: {"node_id":"n_llm","delta":"基于","seq":4}
event: node_completed   data: {"node_id":"n_llm","usage":{"in":812,"out":96},"ms":1830}
event: node_failed      data: {"node_id":"n_http","error":{"code":"HTTP_403","retryable":false}}
event: run_paused       data: {"node_id":"n_hitl","assignee":{"type":"self"},"deadline":"..."}
event: run_completed    data: {"execution_id":9102,"tokens":{"in":2300,"out":410},"ms":9200}
event: run_failed       data: {"execution_id":9102,"error":{"code":"NODE_FAILED","node_id":"n_http"}}
```

规则：`seq` 全局单调递增，前端按 seq 回放与着色；SSE 断线 → 前端用 `GET /executions/{id}/trace?cursor=last_seq` 补齐；token 事件仅在 stream 节点产生。

### 5.2 Trace 链路透传

| 字段 | 产生点 | 透传路径 |
|---|---|---|
| trace_id(=execution_id) | 接入层 | 引擎→M6/M4/M9/M10 全链路日志字段 |
| span(node_id, seq) | 引擎 | 每次节点调用生成，写入 trace_event 与审计 |
| owner_type/owner_id | 接入层 JWT | 所有 DB 写入与 Redis key 组成部分 |
| idempotency_key | 客户端 | 保存/发布/运行入口，24h 去重 |
| 敏感字段 | M7 | 进入 Trace 前按 `sensitive` 标记打码（`sk-****`） |

审计联动：audit 插件记录 api 路径 + trace_id，支持从 Trace 跳转审计、从审计定位 Trace。

## 6. 内部服务接口（模块间契约）

| 调用 | 签名（语义） | 说明 |

| M3→M8 | `check_resource_access(owner, resource_type, resource_id) -> bool` | 保存/发布时引用校验 |
