## 2. 模块拆分清单

### 2.1 模块职责矩阵

| 模块 | 位置 | 核心职责 | 明确不做（边界禁区） |
|---|---|---|---|
| M1 画布编辑器 | 用户侧站点前端 | 图渲染、拖拽连线交互、本地校验（E-101~E-112）、序列化/反序列化 Schema v2 JSON、运行态只读视图与 Trace 叠加 | 不执行任何节点逻辑；不求值变量；不接触凭证；不直接写库 |
| M2 工作流调度引擎 | agent 插件后端 | 图解析、DAG 调度、节点执行、条件/循环/并行、SSE 流式、检查点、取消 | 不做 UI 渲染逻辑；不做配额决策（调用 M9）；不做归属判断（依赖接入层注入的上下文） |
| M3 工作流定义与版本 | agent 插件后端 | 草稿 CRUD、发布生成不可变版本、Schema 版本治理、v1→v2 转换 | 不执行图（交给 M2） |
| M4 RAG 知识库 | agent 插件后端 | 文档解析、切分、向量化编排、召回、重排、引用组装 | 不直接操作 Qdrant（经 M5）；不做向量模型推理（经 M6 Embedding） |
| M5 向量检索服务 | agent 插件后端（适配层） | Qdrant collection 管理（知识库级）、向量读写、payload 过滤、归属映射强校验 | 不做业务归属决策（由 M4/M8 传入）；不做 pgvector（已废弃） |
| M6 LLM 网关 | llm 插件 | 模型路由、凭证托管调用、token 预估与计量上报、Embedding 服务 | 不存储业务数据；不做用户配额扣减（上报给 M9） |
| M7 凭据管理 | llm/工具插件 | 模型 API Key、工具凭证的加密存储与运行时注入 | 不出现在任何 API 响应/导出/Trace 中 |
| M8 权限与归属 | 公共层（接入层+服务层） | JWT 校验、双主体归属过滤、usr 叠加 data_scope、资源授权(ResourceGrant)校验、越权审计 | 不做业务规则；所有模块只消费其判定结果 |
| M9 配额计量 | 公共层（新） | QuotaPlan 定义、QuotaAccount 周期用量、预估拦截（Redis 原子）、结算、额度看板 | 不做计费支付（会员体系已有） |
| M10 日志 Trace | agent 插件 + audit | 执行事件流落库、用户可见 Trace（30 天）、审计事件、Prometheus 指标 | 不记录凭证与敏感原文（internal_debug 仅管理员） |
| M11 身份与组织 | customer 插件（新） | IdentityLink（提示/确认/冷却/解绑）、CustomerOrganization 与成员、HITL 审批人解析 | 不合并资产；不做组织级配额（C-23 边界） |
| M12 发布与交付 | agent 插件后端 | 智能体发布、停用/恢复、站内对话入口、使用看板数据 | 不做开放 API（P1） |

## 3. 编辑态 / 运行态职责边界（红线）

| 维度 | 编辑态（M1，前端） | 运行态（M2，后端） |
|---|---|---|
| 数据 | Schema v2 JSON（nodes/edges/variables/settings） | Execution 实例 + 变量运行时值 |
| 校验 | 结构/类型/连线/必填/资源引用存在性（本地 + 保存时服务端复核） | 服务端发布前全量复核（不信任前端结果） |
| 变量 | 声明与引用检查 | 运行时求值、作用域、敏感值打码 |
| 凭证 | 永不可见（仅显示资源名称） | 由 M7 注入，内存级使用 |
| 执行 | 仅可发起试跑请求 | 全部执行逻辑、重试、取消、检查点 |
| Trace | 渲染层（着色、回放、溯源跳转） | 产生与存储 |
| 版本 | 草稿编辑、导出/导入 JSON | 执行绑定发布版本快照，运行中禁止切换 |

**红线规则**：M1 发出的任何图 JSON 都必须经 M3 服务端校验后才可保存/发布；M2 只接受 M3 校验通过的版本快照执行；前端校验仅用于体验，不构成安全边界。

## 4. 领域数据模型（ER 定义）

### 4.1 实体关系总览（文本 ER）

```
主体域：
  Customer ─1:1─ IdentityLink ─1:1─ User            （L1 关联，Q8）
  Customer ─1:n─ CustomerOrganizationMember ─n:1─ CustomerOrganization   （Q-H）
  MembershipLevel ─n:1─ QuotaPlan ◄─n:1─ Role       （Q-D 双向映射）

工作流域：
  (owner: Customer|User) ─1:n─ Workflow ─1:n─ WorkflowVersion ─1:n─ Execution
  Execution ─1:n─ TraceEvent
  Execution ─1:1─ Checkpoint（线程态）
  Workflow ─1:0..1─ Agent（发布形态）

资源域：
  (owner: Customer|User) ─1:n─ RAGKnowledgeBase ─1:n─ RAGDocument ─1:n─ Chunk
  RAGKnowledgeBase ─1:1─ QdrantCollection（映射，M5 维护）
  ResourceGrant: (owner_type,owner_id) × (resource_type,resource_id) → allow

配额域：
  QuotaPlan ─1:n─ QuotaAccount ─1:n─ UsageRecord
  QuotaAccount: (owner_type,owner_id) 唯一，周期滚动
```

### 4.2 新增表定义

| 表 | 关键字段 | 说明 |
|---|---|---|
| workflow_version | id, workflow_id(FK), version_no, graph_json(Schema v2), schema_version, published_by_type, published_by_id, published_at, status | 不可变快照；执行绑定 |
| quota_plan | id, code, name, scope(cus/usr/both), quota_items(JSON: token/并发/运行数/检索/向量写入), status | Q-D 统一套餐 |
| quota_account | id, owner_type, owner_id, plan_id(FK), period_start, period_end, used(JSON), status | 每主体每周期一行；Redis 计数为准、DB 持久化对账 |
| usage_record | id, owner_type, owner_id, execution_id, node_id, resource_type, amount, tokens_in, tokens_out, cost, created_at | 计量流水（M6/M2 上报） |
| resource_grant | id, owner_type, owner_id, resource_type(model/kb/tool/agent/node_type), resource_id, effect(allow), granted_by, expires_at | M8 授权核心 |
| identity_link | id, customer_id(唯一), user_id(唯一), status(prompted/linked/dismissed), dismissed_until, verified_via, verified_at, audit JSON | Q8/L1；替代 customer.system_user_id 语义 |
| customer_organization | id, name, owner_customer_id(FK), status | Q-H；仅客户域 |
| customer_organization_member | id, org_id(FK), customer_id(FK), role(owner/admin/member), status | HITL 审批人范围解析依据 |

### 4.3 变更表定义

| 表 | 变更 | 迁移 |
|---|---|---|
| workflow | +owner_type, +owner_id, +visibility(private/public/template), +current_version_id, +schema_version | 存量→usr+超管（Q-C） |
| agent | +owner_type, +owner_id, +publish_status | 存量→usr+超管 |
| rag_knowledge_base | +owner_type, +owner_id；created_by 语义废弃（保留列只读）；access_level 收敛为 private/public，dept 迁移为 ResourceGrant | Q-A/Q-C |
| execution | +owner_type, +owner_id, +version_id | 存量→usr+超管 |
| memory | 不改结构；customer_id 语义已随 RK-13 修正；脏数据按 Q-C 清理 | 数据清洗脚本 |
| customer | system_user_id 废弃为只读（迁移至 identity_link） | Q-C |

### 4.4 Qdrant 侧模型（M5）

| 项 | 规则 |
|---|---|
| collection 命名 | `kb_{knowledge_base_id}`，一库一 collection |
| 归属校验 | PG 中 `rag_knowledge_base.owner_*` 为唯一事实源；每次向量操作前 M5 校验调用方对 kb_id 的权限 |
| payload | chunk_id、document_id、kb_id、metadata（标签/来源/页码） |
| 写入顺序 | 先 PG 元数据（事务）→ 后 Qdrant 向量；失败补偿：PG 标记向量状态 pending/failed，后台任务重试 |

## 5. 模块依赖关系

```
M1 画布 ──HTTP──► M3 工作流定义 ──► M8 权限（前置）
                    │
                    ▼
                  M2 引擎 ──► M6 LLM 网关 ──► M7 凭据
                    │  │           │
                    │  │           ▼
                    │  │         M9 配额（预估/结算，Redis）
                    │  ├─► M4 RAG ──► M5 Qdrant 适配
                    │  ├─► 工具/技能（M8 白名单校验）
                    │  └─► M10 Trace
                    ▼
                  M12 发布交付（对话入口 → M2）
M11 身份与组织 ──► M8（审批人解析、关联判定）

依赖红线：
- M1 不得绕过 M3 直连 M2
- M2 不得直接判断归属（消费 M8 上下文）
- M4 不得直连 Qdrant（必经 M5）
- 任何模块不得读取 M7 凭证原文（仅运行时注入）
- M9 拦截发生在 M6 调用前
```
