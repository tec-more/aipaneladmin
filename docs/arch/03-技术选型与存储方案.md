## 1. 选型总览：复用 vs 新增

| 组件 | 结论 | 复用/新增 |
|---|---|---|
| 关系数据库 | PostgreSQL（主）/ openGauss（兼容） | 复用现有 |
| ORM | Tortoise ORM | 复用现有 |
| 向量库 | Qdrant（统一） | 复用现有部署，新增 M5 适配层 |
| 缓存/计数 | Redis | 复用配置，本期启用（Q-G） |
| 消息队列 | RabbitMQ（仅事件总线） | 复用现有，执行链路不接入 |
| 调度器 | 进程内 asyncio + 信号量 | 新增实现，预留 MQ 抽象 |
| Embedding 服务 | llm 插件 embedding_factory | 复用，扩展授权校验 |
| LLM 接入网关 | llm 插件（模型路由+凭证） | 复用，扩展用户计量 |
| 用户侧前端 | Vue3 + Vite + Pinia + VueFlow ^1.48.2 | 新增站点，同栈 |
| 凭据加密 | AES-GCM，应用层加密 | 新增（见 §2.7 对比） |

## 2. 分项选型对比

### 2.1 关系数据库（已决：PostgreSQL + openGauss 兼容）

| 方案 | 利 | 弊 | 结论 |
|---|---|---|---|
| 仅 PostgreSQL | 现有底座，零成本 | 不满足 Q-I | 否 |
| **PG 主 + openGauss 兼容** | 国产化私有化可交付；协议兼容 | SQL 需规避 PG 专有特性；需部署测试 | **采纳** |
| 切 MySQL | 生态广 | 全量重写迁移，pgvector/jsonb 语义丢失 | 否 |

openGauss 兼容清单（开发红线）：

| 禁用 | 替代 |
|---|---|
| `gen_random_uuid()` 等 pgcrypto 函数 | 应用层生成 UUID/ULID |
| `ON CONFLICT` 复杂用法（部分索引谓词） | 简单 `ON CONFLICT DO UPDATE` 或应用层先查后写 |
| PG 专有索引类型（GIN/GiST 部分场景） | B-tree / 普通复合索引；jsonb 查询用 `->>` 后建表达式索引需验证，优先冗余列 |
|  advisory lock | Redis 分布式锁 |
| `RETURNING` 深度依赖 | Tortoise 已抽象，避免手写 |

### 2.2 向量库（已决：Qdrant 统一）

| 方案 | 利 | 弊 | 结论 |
|---|---|---|---|
| pgvector | 零组件、事务一致 | 归属行级过滤强但大规模弱；Q-B 已否 | 废弃（存量迁移） |
| **Qdrant** | 性能、过滤、已有部署 | 两库一致性需补偿；隔离靠服务层 | **采纳** |
| 双引擎 | 灵活 | 隔离做两套，RK-04 翻倍 | 否 |

部署规格建议：私有化单实例 Qdrant，开启快照备份（每日）；collection 数上限按知识库数估算（单用户 ≤ 50 KB × 5000 用户 ≈ 25 万 collection 超限 → **改为"按套餐限制 KB 数"**：基础 5 / VIP 20 / SVIP 100，P0 可承载）。

### 2.3 缓存/计数（已决：启用 Redis）

| 用途 | Key 设计 | TTL |
|---|---|---|
| 配额周期计数 | `quota:{owner_type}:{owner_id}:{item}:{period}` → INCRBY | 到周期末 |
| 配额预估占用 | `quota_hold:{execution_id}` → Hash，确认后转正式或释放 | 运行结束即清 |
| 并发执行计数 | `conc:{owner_type}:{owner_id}` / `conc:global` → INCR/DECR | 带看门狗（60s 兜底） |
| 分布式锁 | `lock:{resource}` SET NX PX | 30s |
| 幂等键 | `idem:{endpoint}:{key}` | 24h |
| 执行状态（运行中） | `exec:state:{execution_id}` → Hash（节点进度） | 结束后 1h |
| 限流（发送验证码等） | `rl:{scene}:{identity}` | 滑动窗口 |

降级：Redis 不可用 → 配额预检放行但 DB 兜底强校验（容忍短暂超用，结算修正），并发控制退化为 DB 计数。节点 5 详化。

### 2.4 消息队列（已决：仅事件总线）

| 方案 | 结论 |
|---|---|
| 审计/通知/邮件事件 | 走 RabbitMQ（现有 event_bus） |
| 工作流执行 | **不走 MQ**（Q-E），但引擎入口抽象为 `ExecutorBackend` 接口（`InProcessBackend` P0 实现，`MqBackend` P1+ 可插拔） |

### 2.5 调度器（新增实现）

| 方案 | 利 | 弊 | 结论 |
|---|---|---|---|
| **asyncio + 全局/用户双级信号量** | 零新组件；与现有 SSE 模型一致 | 单进程天花板（NFR: 全局 50） | **P0 采纳** |
| arq/dramatiq 等任务队列 | 成熟重试 | 引入新中间件语义，私有化增重 | 否 |
| RabbitMQ worker | 水平扩展 | 运维复杂 | P1+ 预留 |

实现要点：全局信号量 50 + 用户信号量（套餐值）；超限即拒（429 语义）；执行上下文对象携带 `owner/quota/trace_id`；所有阻塞 IO 必须 async。

### 2.6 Embedding 服务

| 方案 | 结论 |
|---|---|
| 复用 embedding_factory，扩展"按授权清单过滤模型" | **采纳**；向量化调用走 M6 网关统一计量（tokens 或字符折算） |
| 独立 Embedding 微服务 | 否（私有化增重，P0 无必要） |

### 2.7 凭据加密（新增，需选型）

| 方案 | 利 | 弊 | 结论 |
|---|---|---|---|
| **AES-GCM 应用层加密，主密钥环境变量** | 零依赖、可审计、密钥可轮换（密文带版本号） | 主密钥保护靠部署纪律 | **采纳** |
| Vault/KMS | 专业密钥管理 | 私有化引入重型组件 | 否（P2 可选） |
| 明文 + DB 权限 | 最简单 | 违反 C-10 | 否 |

规则：密文入库 `cipher:v1:...`；仅 M7 可解密；解密发生在调用前内存中；日志/Trace/导出全域屏蔽。

### 2.8 用户侧前端

| 方案 | 结论 |
|---|---|
| Vue3 + Vite + Pinia + VueFlow ^1.48.2 + Element Plus（换主题） | **采纳**：与 web 同栈，依赖版本一致，构建工具链复用；独立 `web-user/` 目录 |
| 独立 UI 库（Naive UI 等） | 否：双 UI 库维护成本，团队无收益 |

### 2.9 Token 预估方案（C-05 配套）

| 方案 | 利 | 弊 | 结论 |
|---|---|---|---|
| **字符启发式（tokens ≈ chars/3.5，中文保守 /1.5）+ 结算用供应商真实 usage** | 零依赖、任意模型可用 | 偏差 ±20%（符合 NFR） | **采纳** |
| tiktoken 全量 | 准 | 仅适配 OpenAI 系；私有模型失准 | 辅助可选 |
| 不预估 | 无法实现前置拦截 | 违反 C-05 | 否 |

## 3. 存储方案详细设计

### 3.1 工作流定义 JSON

| 项 | 方案 |
|---|---|
| 载体 | `workflow_version.graph_json`（PG JSONB 列，Tortoise JSONField） |
| Schema | v2（统一前后台）；v1 存量图经转换器升级后写入新版本 |
| 大小约束 | 单图 ≤ 200 节点，JSON ≤ 2MB，超限拒绝保存 |
| 查询模式 | 从不按 JSON 内容检索；元数据（名称/状态/归属）全部冗余为列 |
| openGauss | JSONB 可用；不做 jsonb 路径索引 |

### 3.2 向量集合（Qdrant）

| 项 | 方案 |
|---|---|
| collection | `kb_{knowledge_base_id}`，创建知识库时同步创建 |
| 向量维度 | 以知识库 `vector_dimension` 为准，创建后不可变（变更需重建库） |
| 距离度量 | cosine（统一） |
| payload 索引 | `document_id`(keyword)、`created_at`(datetime)、业务标签字段按需（keyword） |
| 归属隔离 | 检索入口必须携带 kb_id 列表（由 M8 计算可访问集合）；M5 对每次调用复核 kb 归属 |
| 删除 | 删文档=按 document_id 过滤删除；删库=删 collection；注销=硬删（Q-J） |

### 3.3 执行日志 / Trace

| 项 | 方案 |
|---|---|
| 表 | `trace_event`：execution_id, seq, event_type, node_id, payload(JSON), created_at |
| 写入 | 执行中批量缓冲（每 20 条或 1s flush），避免逐条写库占用连接池（C-11） |
| 读取 | 按 execution_id + seq 分页；运行中经 Redis `exec:state` 直读 |
| 保留 | 用户可见 30 天 → 定时清理任务物理删除，保留聚合指标（M10 汇总表） |
| 量级 | 5000 事件/次 × 峰值 500 次/日 ≈ 250 万行/日 → 30 天 7500 万行，**必须按周分区或按日清理**；选型：不做分区（openGauss 兼容优先），走"每日清理 + (execution_id,seq) 索引" |

### 3.4 会话记忆

| 项 | 方案 |
|---|---|
| 表 | 沿用现有 `memory`（customer_id/user_id 双列，语义已对齐 owner） |
| 隔离 | 查询必须带主体列 + ID；会话级短期记忆可入 Redis（`mem:session:{session_id}`，TTL 7 天）减轻 DB |
| 清理 | 注销硬删（Q-J）；短期记忆到期自动失效 |

### 3.5 文件存储

| 项 | 方案 |
|---|---|
| 路径 | `storage/{owner_type}/{owner_id}/{session_id}/{file_id}_{safe_name}` |
| 约束 | 类型白名单、大小按套餐、路径遍历防护（ID 化命名） |
| 清理 | 会话过期保留 7 天；注销硬删 |
| 私有化 | 本地磁盘；不引入对象存储（P2 可选） |

### 3.6 配额数据

| 项 | 方案 |
|---|---|
| 事实源 | Redis 计数（实时）+ PG `quota_account.used`（每分钟异步对账落盘） |
| 流水 | `usage_record` 每次结算写入；保留 13 个月（对账），之后按月聚合入 `usage_rollup` |
| 崩溃恢复 | Redis 数据丢失 → 以 PG 已落盘值重建，低估方向恢复（宁可少计，随后结算修正） |

## 4. 索引策略

| 表 | 索引 | 用途 |
|---|---|---|
| workflow | (owner_type, owner_id, visibility) / (current_version_id) | 我的列表 / 版本反查 |
| workflow_version | UNIQUE(workflow_id, version_no) | 版本定位 |
| execution | (owner_type, owner_id, created_at DESC) / (workflow_id, version_id) / (status, created_at) | 历史列表 / 版本实例 / 运行中扫描 |
| trace_event | (execution_id, seq) / (created_at) | 回放 / 清理 |
| usage_record | (owner_type, owner_id, created_at) / (execution_id) | 账单 / 单次追溯 |
| quota_account | UNIQUE(owner_type, owner_id) | 账户定位 |
| resource_grant | UNIQUE(owner_type, owner_id, resource_type, resource_id) / (resource_type, resource_id) | 授权判定 / 资源反查 |
| identity_link | UNIQUE(customer_id) / UNIQUE(user_id) | 关联查询 |
| customer_organization_member | (customer_id, status) / (org_id, status) | 成员解析 / 组织成员列表 |
| rag_knowledge_base | (owner_type, owner_id) / (is_public) | 我的库 / 公共库 |
| memory | (customer_id, agent_id) / (user_id, agent_id) | 记忆召回 |

原则：所有列表查询必须命中 (owner_*, ...) 前缀索引；不写 jsonb 路径索引（openGauss 红线）；大表清理字段（created_at）必带索引。

## 5. 冷热数据分层

| 层 | 内容 | 介质 | 策略 |
|---|---|---|---|
| 热（秒级） | 配额计数、并发计数、执行状态、会话短期记忆、幂等键 | Redis | TTL 自动过期；崩溃从 PG 重建 |
| 温（分钟~30 天） | 工作流/版本、执行实例、Trace、记忆（长期）、usage 流水 | PG | 行级索引；Trace 30 天清理 |
| 冷（30 天+） | 聚合指标（成功率/耗时/token 汇总）、usage_rollup（13 个月+）、审计（90 天，现有策略） | PG 聚合表 | 只保留聚合，明细物理删除 |
| 归档 | 审计日志按现有 audit 保留策略；无新增归档介质 | PG/日志文件 | 不引入新组件 |

定时任务（复用现有调度框架）：Trace 清理（每日凌晨）、usage 对账落盘（每分钟）、usage 月聚合（每月 1 日）、临时文件清理（每日）、Qdrant 快照（每日）。
