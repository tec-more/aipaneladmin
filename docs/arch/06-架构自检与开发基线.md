## 1. 架构自检

### 1.1 耦合检查

| 检查项 | 结论 | 处理 |
|---|---|---|
| M2 引擎 ↔ 归属判断 | 引擎不判断归属，消费 M8 上下文 | 已解耦 ✅ |
| M4 RAG ↔ Qdrant | 必经 M5 适配层 | 已解耦 ✅ |
| M1 画布 ↔ M2 引擎 | 必经 M3 校验，无直连 | 已解耦 ✅ |
| M9 配额 ↔ M6 网关 | 单向：M2 编排，M6 仅上报用量 | 已解耦 ✅ |
| customer 插件 ↔ agent 插件 | 经 M11 服务接口（resolve_assignee/link-status），无模型交叉引用 | 已解耦 ✅ |
| 既有后台画布 ↔ Schema v2 | 双轨共享 schema，v1 转换器单向升级 | 受控耦合，需转换器回归测试（高风险，见 §3） |
| 会员体系 ↔ 配额 | MembershipLevel/Role → QuotaPlan 单向映射 | 已解耦 ✅ |

### 1.2 性能瓶颈

| 瓶颈 | 分析 | 对策 |
|---|---|---|
| DB 连接池 20 | 50 并发执行 + SSE 长连接下，逐条落库会打满 | Trace 批量缓冲（20 条/1s flush）；执行状态外置 Redis；HITL 不占连接 ✅ |
| 单进程执行天花板 | 全局信号量 50 是承诺上限 | NFR 已对齐；接口预留 MQ 执行器 ✅ |
| Trace 7500 万行/月 | 大表查询与清理压力 | (execution_id,seq) 索引 + 每日清理 + 30 天硬边界 ✅ |
| Qdrant collection 数量 | KB 套餐上限 5/20/100 控制总量 | 已限制 ✅ |
| 配额对账频率 | 每分钟全量对账可能扫表 | 仅对账活跃账户（Redis 有计数的 owner），避免全表 ✅ |

### 1.3 单点故障

| 单点 | 影响 | P0 立场 |
|---|---|---|
| 应用进程 | 全量服务中断 | 私有化单实例现实（NFR 已声明无 HA）；进程守护 + 崩溃后实例标记 interrupted 可查 |
| Redis | 配额/并发降级 | 降级矩阵已覆盖（§05-1.1） |
| Qdrant | RAG 全失效 | 快照每日备份；降级策略已定义 |
| PG | 全失效 | 私有化标准备份（现有运维范畴） |

### 1.4 扩展瓶颈（P1+ 预留）

| 场景 | 触发条件 | 预留点 |
|---|---|---|
| 执行水平扩展 | 并发 > 50 常态 | ExecutorBackend 抽象 → MqBackend |
| 开放 API | P1 需求 | /v1/u 契约已独立，可加 API Key 鉴权面 |
| 向量规模增长 | 单 KB > 100 万 chunk | Qdrant shard 配置预留 |
| 组织级共享配额 | C-23 边界外 | QuotaAccount.owner 已多态，可扩展 owner_type=org |

## 3. 取舍 Trade-off 说明

| 取舍点 | 选择 | 放弃 | 理由 |
|---|---|---|---|
| 单引擎纵向分域 vs 双引擎 | 单引擎改造 | 彻底隔离 | 避免节点语义双轨漂移；隔离在数据/服务层实现已足够 |
| 进程内执行 vs MQ 工作进程 | 进程内 + 抽象预留 | 水平扩展能力 | 私有化单实例现实；运维简单优先 |
| Qdrant 统一 vs pgvector 零组件 | Qdrant | 少一个组件的部署 | 检索性能与功能上限；已有部署 |
| 一 KB 一 collection vs 共享 collection + payload 过滤 | 一 KB 一 collection | 跨库联合检索便利 | 隔离边界清晰、删除彻底；跨库由多 KB 列表在应用层合并 |
| 字符启发式预估 vs tokenizer 精确预估 | 启发式 | 精确性 | 多模型通用、零依赖；±20% 满足前置拦截目标 |
| Trace 每日清理 vs 分区表 | 每日清理 | 长周期明细查询 | openGauss 兼容优先；30 天业务承诺足够 |
| 凭据应用层加密 vs Vault | AES-GCM 自管 | 专业密钥管理 | 私有化零新增组件；风险用轮换与纪律对冲 |
| 提示注入缓解+声明 vs 输入输出强审查 | 缓解+声明 | 更强安全 | 强审查误伤可用性且仍非绝对防御；产品边界声明更诚实 |

## 6. 开发基线 & 编码约束（下游必须遵守）

### 6.1 强制规约（违反即评审不通过）

| 编号 | 规约 | 溯源 |
|---|---|---|
| R-01 | 所有 ORM 查询必须经归属过滤中间件，禁止手写绕过；越权返回 404 | C-01/§05-2.1 |
| R-02 | 引擎只消费 M8 上下文，禁止在引擎内做 JWT/归属判断 | §02-5 |
| R-03 | 前端校验不构成安全边界；保存/发布必须服务端全量复核 | §02-3 |
| R-04 | token 签发必须 typ/sub 同源；禁止跨表借用 ID | RK-13/D3 |
| R-05 | 凭据仅 M7 解密；禁止落日志/Trace/导出；密文格式 `cipher:v1:` | §05-2.3 |
| R-06 | SQL 遵守 openGauss 红线（禁 pgcrypto 函数/复杂 ON CONFLICT/GIN/advisory lock/手写 RETURNING） | §03-2.1 |
| R-07 | 新模型随启动一次性注册，禁止运行时热注册；插件启用态与模型注册解耦 | C-21 |
| R-08 | 阻塞 IO 必须 async；禁止在事件循环中跑同步解析/请求 | §03-2.5 |
| R-09 | 配额预占先于一切外部调用；结算携带 (execution_id,node_id,seq) 幂等键 | C-05/§05-1.2 |
| R-10 | 用户域禁止 code 节点；http 节点强制域名白名单 + DNS 二次校验 | C-04/§05-2.5 |
| R-11 | Trace 批量缓冲写入；禁止逐条 INSERT | §03-3.3 |
| R-12 | 日志必带 trace_id/owner；禁止记录凭证与 prompt 全文 | §05-3.2 |
| R-13 | 向量操作必经 M5 且复核 PG 归属；禁止业务代码直连 Qdrant | §02-5 |
| R-14 | 身份关联仅走"提示→主动确认→验证"流程；禁止任何自动绑定代码路径 | §3.3/RK-14 |
| R-15 | 错误码按段位返回；校验错误必须携带 E-1xx 明细 | §04-2.3 |

### 6.2 目录与命名约束

| 项 | 约定 |
|---|---|
| 用户侧 API | `base/plugins/agent/api/v1/u/` 新目录（或独立 router 前缀 `/v1/u`），与既有管理侧分离 |
| 用户侧前端 | `web-user/` 独立工程，依赖版本与 `web/` 对齐（VueFlow ^1.48.2） |

| 新服务 | M9 → `base/common/quota/`；M11 → `base/plugins/customer/services/identity_service.py` 等 |
