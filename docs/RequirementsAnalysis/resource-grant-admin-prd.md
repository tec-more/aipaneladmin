## 1. 背景与目标

### 1.1 现状问题

平台资源（模型 / 知识库 / 工具 / 智能体 / 节点类型）采用**显式授权**策略：默认不放行，存在有效授权记录才允许访问。当前后端已提供授权发放 / 撤销 / 反查能力，但**只开放了 API，没有管理后台界面**（既有裁定：仅 API，无后台 UI）。

由此产生的实际问题：

- 终端用户（customer）侧资源卡片默认锁定，提示"暂无资源权限"，这是显式授权策略的正常表现；
- 但当运营需要给某个用户开放资源时，管理员**只能通过手动调用 API 完成授权**——无可视化入口、操作门槛高、容易填错主体或资源、也无法直观查看"某资源当前授权给了谁 / 某用户被授权了哪些资源"。

### 1.2 产品决策

在管理后台新增**资源授权管理**界面，将已有的授权 API 能力包装为可视化操作，使超级管理员可以：

1. 直观地发放授权（选资源 → 选主体 → 确认）；
2. 查看授权现状（按主体、按资源两个视角）；
3. 撤销授权（回收误发或到期的权限）；
4. 所有授权变更留痕可审计。

### 1.3 预期结果（可观察）

- 超级管理员无需调用 API，即可在后台完成一次资源授权，终端用户刷新后即可看到对应资源解锁可用；
- 误发的授权可在后台一键撤销，终端用户对应资源恢复锁定；
- 任意一条授权都能查到"谁授权的、何时授权、何时过期"。

## 2. 范围

### 2.1 核心旅程（P0）

超级管理员完成一次资源授权的最小完整路径：

1. 进入「资源授权」管理页；
2. 发起新建授权，选择一个资源；
3. 选择一个或多个授权主体；
4. 确认提交，授权直接生效；
5. 在列表看到新生成的授权记录，主体端对应资源解锁。

**恢复路径**：误授权时，在列表对目标记录执行撤销，确认后权限回收，主体端恢复锁定。

### 2.2 P0 / P1 边界

| 优先级 | 能力 |
|---|---|
| **P0** | 授权记录列表浏览；新建授权（单资源 + 多主体）；撤销授权；按资源类型 / 主体类型筛选 |
| **P1** | 按资源反查被授权主体视图；按主体反查已授权资源视图；过期时间设置与到期状态展示；操作审计记录查看入口 |

### 2.3 明确排除（本期不做）

- **审批流**：授权直接生效，不经二级审批（已与需求方确认）；
- **矩阵式批量授权**：不做"资源 × 主体"二维批量勾选，本期支持"单资源 + 多主体"；
- **授权申请流程**：不开放主体侧"申请授权"入口，授权完全由管理员主动发起；
- **隐式授权**：不引入"发布即公开"等任何隐式放行规则，授权判定逻辑保持不变。

## 3. 产品模型

### 3.1 角色

| 角色 | 说明 | 与本模块关系 |
|---|---|---|
| 超级管理员（superuser） | 平台最高权限管理员 | 唯一可执行授权发放 / 撤销 / 查看的角色 |
| 终端用户（customer） | C 端注册用户 | 授权的**主体**之一，被授权后获得资源访问能力 |
| customer 组织 | customer 所属组织 | 授权的主体之一，组织全体成员获得授权 |
| 后台用户（usr） | 管理后台账号 | 授权的主体之一，用于内部资源协作 |

### 3.2 核心业务对象：资源授权记录

一条授权记录表达"**某主体被允许访问某资源**"。其唯一性由四元组决定：**主体类型 + 主体 ID + 资源类型 + 资源 ID**，同一组合只存在一条有效记录。

| 概念 | 说明 |
|---|---|
| 主体类型 | customer / 组织 / 后台用户（usr）三类 |
| 资源类型 | 模型 / 知识库 / 工具 / 智能体 / 节点类型，共五类 |
| 过期时间 | 可选；为空表示长期有效，到期后授权自动失效 |
| 授权人 | 执行授权操作的管理员标识，自动记录 |
| 授权时间 | 记录生成时间，自动记录 |

### 3.3 核心流程

```
超级管理员
   │ 进入「资源授权」页
   ▼
新建授权
   │ ① 选资源类型 → ② 选具体资源（单选）
   │ ③ 选主体类型 → ④ 选一个或多个主体
   │ ⑤（可选）设置过期时间
   ▼
确认提交 ──→ 系统校验（资源有效 / 主体有效 / 过期时间合法）
   │
   ▼
逐主体生成授权记录（已存在的组合按幂等规则刷新）
   │
   ▼
直接生效 + 写审计日志 ──→ 列表出现新记录，主体端资源解锁
```

## 4. 功能需求

### FR-01 模块入口与访问权限

**目的**：为 superuser 提供资源授权管理入口，并对非授权角色彻底隐藏。

**触发与权限**：

- 入口位于管理后台导航中，归属系统管理 / 权限管理分组下，菜单名「资源授权」。`[Assumption：具体菜单位置待与后台信息架构对齐]`
- **仅 superuser 可见该菜单、可进入该页面**；非 superuser 用户菜单不渲染、直接访问 URL 时被拦截并提示无权限。
- 与后端鉴权保持一致：所有授权操作接口仅接受 superuser 调用，前端隐藏不改变后端校验（前端隐藏是体验层，后端校验是安全层）。

**结果与状态**：superuser 进入页面后默认展示授权记录列表（FR-02）。

**异常**：非 superuser 通过拼接 URL 访问时，展示无权限提示页，不加载任何授权数据。

---

### FR-02 授权记录列表

**目的**：让管理员一眼看清"当前存在哪些有效授权"。

**布局**：顶部筛选区 + 列表区 + 操作列。

**列表字段**：

| 字段 | 说明 |
|---|---|
| 主体 | 主体类型徽标（customer / 组织 / 后台用户）+ 主体标识（customer 显示邮箱、组织显示组织名、usr 显示用户名） |
| 资源 | 资源类型徽标（模型/知识库/工具/智能体/节点类型）+ 资源名称 |
| 授权人 | 执行授权的管理员 |
| 授权时间 | 记录生成时间 |
| 过期时间 | 过期时间；为空显示"长期有效" |
| 状态 | 生效中 / 已过期（见共享规则 §5.2） |
| 操作 | 撤销（FR-04） |

**处理规则**：

- 默认按授权时间倒序排列；
- 仅展示**现存**授权记录（生效中 + 已过期）；已撤销的记录不在列表出现（撤销即移除，见 FR-04）；
- 资源已被删除的授权记录仍保留展示，并标注"资源已删除"（§6.2），便于追溯与手动清理；
- 空状态：暂无授权记录时，展示空态文案与「新建授权」引导按钮。

**异常**：列表加载失败时展示错误提示与重试入口，不展示残缺数据。

---

### FR-03 新建授权（核心）

**目的**：管理员完成一次"单资源 + 多主体"的授权发放。

**触发**：superuser 在列表页点击「新建授权」，弹出授权表单。

**表单字段**：

| 字段 | 必填 | 规则 |
|---|---|---|
| 资源类型 | 是 | 单选下拉：模型 / 知识库 / 工具 / 智能体 / 节点类型 |
| 资源 | 是 | 级联选择器，随资源类型加载该类型下可授权资源，**单选**；选择器内应展示资源名称及状态（如已发布/草稿），仅可选择**当前可授权**的资源 |
| 主体类型 | 是 | 单选：customer / customer 组织 / 后台用户 |
| 主体 | 是 | 级联选择器，随主体类型加载，**多选，至少选择 1 个**；customer 按邮箱搜索、组织按名称搜索、usr 按用户名搜索 |
| 过期时间 | 否 | 日期时间选择；为空表示长期有效；若填写必须晚于当前时间 |

**处理规则**：

1. 提交前逐项校验：资源已选、主体不少于 1 个、过期时间（若填）晚于当前时间；任一不满足则在对应字段下方给出提示，阻断提交。
2. 校验通过后，对**每一个选中主体**生成一条针对该资源的授权记录。
3. **幂等**：若某"主体 + 资源"组合已存在有效授权，不报错、不产生重复记录，按既有规则处理（刷新该组合的过期时间为本次提交值；**测试节点1 Q4 裁定：本次提交未填过期时间时保持原过期时间不变，不刷为永久**——防止误操作导致授权范围扩大）；提交结果中需区分"新增"与"已存在并刷新"两类反馈。
4. **直接生效**：授权无需审批，提交成功即生效。

**结果与状态**：

- 成功：提示授权完成，说明"新增 N 条、刷新 M 条"，列表插入/更新对应记录，主体端对应资源即时解锁；
- 失败：接口异常时提示失败原因并允许重试；多主体提交采用**逐条独立**语义（§6.4）——成功的主体正常生效、失败的主体明确报告明细，不做整体回滚，失败项可安全重试（授权幂等）。

**权限**：仅 superuser 可提交；非 superuser 无入口（FR-01）。

**异常**：资源在提交瞬间被删除/下架、主体在提交瞬间被禁用等竞态，提交时由后端校验并返回明确错误，前端提示后允许管理员调整重试。

---

### FR-04 撤销授权

**目的**：回收误发或不再需要的授权，使对应资源对主体恢复锁定。

**触发**：superuser 在列表某条记录点击「撤销」。

**处理规则**：

1. **二次确认**：撤销属于权限回收的后果操作，点击后弹出确认框，明确展示"将对【主体】回收【资源】的访问权限"，需管理员确认后才执行；
2. 确认后立即生效：移除该授权记录，主体端对应资源即时恢复锁定；
3. **幂等**：对同一记录重复撤销（如多端同时操作）不产生错误，返回一致结果；
4. 撤销操作写审计日志。

**结果与状态**：撤销成功后该记录从列表消失，给出"已撤销"提示。

**异常**：撤销失败（如记录已被他人撤销）时提示实际状态并刷新列表。

---

### FR-05 资源选择器

**目的**：在新建授权时，按资源类型提供可授权资源的浏览与选择。

**触发与规则**：

- 随「资源类型」切换，加载该类型下当前可被授权的资源列表；
- 支持按名称搜索；
- 仅展示**当前存在且处于可授权状态**的资源；已删除资源不出现；
- 选择器内对资源状态做可见标注（如智能体的已发布/草稿），帮助管理员判断授权对象是否正确。

**异常**：某资源类型下无可授权资源时，选择器展示空态提示，不允许空提交。

---

### FR-06 主体选择器

**目的**：在新建授权时，按主体类型提供授权对象的搜索与多选。

**触发与规则**：

- 随「主体类型」切换，加载对应主体的选择方式：
  - customer：按邮箱搜索选择；
  - customer 组织：按组织名称搜索选择，选中即代表**该组织全体成员**获得授权，且**成员变动自动生效**（新成员加入自动获得、退出自动失去；依据 §6.1 判定侧 org 维度裁定）；
  - 后台用户：按用户名搜索选择；
- 支持多选，已选主体以标签形式展示，可单个移除；
- 仅展示**当前有效**的主体（已禁用/已删除主体不可选）。

**异常**：搜索无结果时展示空态；未选择任何主体时阻断提交（FR-03 校验）。

---

### FR-07 查询与筛选

**目的**：支持管理员从"资源"和"主体"两个视角追溯授权现状。

**P0 筛选**（列表页顶部）：

| 筛选项 | 说明 |
|---|---|
| 资源类型 | 按五类资源过滤 |
| 主体类型 | 按 customer / 组织 / 后台用户过滤 |
| 状态 | 生效中 / 已过期 |
| 关键词 | 按主体标识或资源名称模糊搜索 |

**P1 反查视图**：

- 按资源反查：查看某资源当前被授权给了哪些主体（对应后端"按资源反查被授权主体"能力）；
- 按主体反查：查看某主体当前被授权了哪些资源。

## 5. 共享规则与异常

### 5.1 权限矩阵

| 能力 | superuser | 其他管理员 | customer / usr（作为主体） |
|---|---|---|---|
| 进入资源授权页 | ✅ | ❌ | ❌ |
| 新建授权 | ✅ | ❌ | ❌ |
| 撤销授权 | ✅ | ❌ | ❌ |
| 查看授权列表 / 审计 | ✅ | ❌ | ❌ |

唯一权威定义：本模块所有能力仅 superuser 可用，前端隐藏与后端校验双重保证。

### 5.2 授权有效性规则

- **显式授权，不隐式放行**：主体对某资源的访问权限，完全取决于是否存在对应的有效授权记录；不存在记录即视为无权限。
- **生效中**：当前时间早于过期时间，或无过期时间（长期有效）。
- **已过期**：当前时间晚于过期时间；过期授权**不再放行**，记录保留在列表中并标注"已过期"，便于追溯，可由管理员撤销清理。
- **主体有效性校验**：判定时追加校验主体状态——已禁用/删除的主体即使存在有效授权记录也不放行；主体恢复后授权自动恢复（依据 §6.3 裁定）。
- **资源有效性标注**：资源被删除后，其授权记录保留并标注"资源已删除"，不再放行，可审计追溯（依据 §6.2 裁定）。
- **组织维度解析**：主体为 customer 时，判定时除查其自身授权外，追加查其所属组织的授权记录（依据 §6.1 裁定）。
- 本模块只负责授权记录的发放/撤销/展示；除 §6.1 新增组织维度外，**不改变**授权判定的其余逻辑。

### 5.3 幂等规则

- 重复授权同一"主体 + 资源"组合：不产生重复记录，按规则刷新过期时间（FR-03）；
- 重复撤销同一记录：返回一致结果，不报错（FR-04）。

### 5.4 审计规则

- 授权的**发放**与**撤销**均须记录审计日志，包含：操作人、操作类型（发放/撤销）、主体、资源、过期时间、操作时间；
- 审计日志面向合规追溯，本期提供查看入口（P1），不提供编辑或删除。

### 5.5 关键异常一览

| 场景 | 产品行为 |
|---|---|
| 重复授权 | 幂等处理，反馈"已存在并刷新"（FR-03） |
| 撤销不存在/已被撤销的记录 | 幂等返回，提示实际状态并刷新（FR-04） |
| 过期时间早于当前时间 | 表单校验阻断（FR-03） |
| 提交时资源/主体被删除或禁用 | 后端校验返回错误，提示后允许调整重试（FR-03） |
| 多主体部分失败 | 明确告知成功/失败明细，不留半完成状态（FR-03） |
| 列表/选择器加载失败 | 错误提示 + 重试入口，不展示残缺数据 |
| 非 superuser 访问 | 菜单隐藏 + URL 拦截 + 后端拒绝（FR-01） |

## 6. 已裁定决策（原开放问题）

以下 4 项原开放问题已与需求方对齐裁定：

| # | 问题 | 裁定 | 产品含义 |
|---|---|---|---|
| 6.1 | 组织授权落地方式 | **判定侧新增 org 维度** | 授权记录的主体类型新增"组织"取值；授权判定时，除查主体自身授权外，追加查其**所属组织**的授权。**成员变动自动生效**：新成员加入自动获得组织授权、退出自动失去，无需逐条维护成员级记录 |
| 6.2 | 资源删除后历史授权记录 | **保留标注** | 授权记录保留并标注"资源已删除"，不再放行但可审计追溯，由管理员手动撤销清理；不做级联删除，保留授权轨迹 |
| 6.3 | 主体被禁用/删除后授权记录 | **判定侧校验有效性** | 授权记录保留；判定时追加校验主体有效性——已禁用/删除的主体即使存在授权也不放行；主体恢复后授权自动恢复，无需重新授权 |
| 6.4 | 多主体提交部分失败语义 | **逐条独立** | 成功的主体正常生效、失败的主体报告明细，不做整体回滚；授权幂等、无资金风险，失败项可安全重试 |

> **6.1 为结构性裁定**：底层授权记录的主体类型需支持"组织"取值，授权判定逻辑需扩展组织成员关系解析。这是本期**唯一涉及授权判定逻辑变更**的点，需架构设计承接；其余 3 项均为既有模型上的规则明确，不改变数据结构。
